# Knowledge Base API

REST API for a personal knowledge base: users store documents in collections and ask questions about them. Answers are generated by a local LLM via [Ollama](https://ollama.com) — no external API keys and no per-token billing.

## Stack

- **Python 3.12+** (Docker image: `python:3.12-slim`)
- **Django 6.1.2**, **Django REST Framework 3.18.3**
- **PostgreSQL 16**
- **Ollama** (local inference, `llama3.1` / `qwen3:8b` and others)
- **Docker** + **Docker Compose**
- **drf-spectacular** (OpenAPI 3 + Swagger UI), **django-filter**
- **pytest** + **pytest-django** + **pytest-cov**, **ruff**, **black**

## Prerequisites

- **Docker** + **Docker Compose** (the only hard requirement for the default setup)
- For local runs without Docker:
  - Python 3.12+
  - PostgreSQL 16
  - [Ollama](https://ollama.com) with the chosen model
- ~5 GB free disk for the `llama3.1` model (~4.7 GB download)

## Quick start

1. Clone the repository:

   ```bash
   git clone <repo-url>
   cd knowlage-base-api
   ```

2. Create `.env` (template: `.env.example`):

   ```bash
   cp .env.example .env
   ```

3. Fill in `.env`. The `db`, `ollama`, and `web` services in `docker-compose.yml` already have working defaults (database `knowledge_base`, user `kb_user`, password `kb_password`), so these variables are optional for Docker. They are shown here for clarity; the values must stay consistent with `DATABASE_URL` (db name/user/password) if you change them:

   ```dotenv
   SECRET_KEY=change-me
   DEBUG=True
   ALLOWED_HOSTS=localhost,127.0.0.1

   # Compose overrides DATABASE_URL / OLLAMA_URL for the web container
   # and points them at the db / ollama services.
   # For local runs (without Docker) use localhost instead.
   DATABASE_URL=postgres://kb_user:kb_password@localhost:5432/knowledge_base
   OLLAMA_URL=http://localhost:11434/api/chat
   OLLAMA_MODEL=llama3.1

   POSTGRES_DB=knowledge_base
   POSTGRES_USER=kb_user
   POSTGRES_PASSWORD=kb_password
   ```

   > For local runs (without Docker), `DATABASE_URL` and `OLLAMA_URL` point to `localhost`.

4. Start the stack:

   ```bash
   docker compose up --build
   ```

   Migrations run automatically (via `entrypoint.sh`). Swagger and the API will be available at `http://localhost:8000`.

   > ⚠️ This setup runs Django's `runserver` in the `web` container — fine for development and review, **not** for production. For production use `gunicorn` + `nginx` + HTTPS.

5. Create a user (for the API and the admin):

   ```bash
   docker compose exec web python manage.py createsuperuser
   ```

6. Open the docs: **http://localhost:8000/api-docs/**

## Setting up Ollama

Docker variant (the `ollama` service is already in `docker-compose.yml`):

```bash
docker compose exec ollama ollama pull llama3.1
```

Verify:

```bash
docker compose exec ollama ollama list
curl http://localhost:11434/api/tags
```

Local variant (Ollama installed on the host):

```bash
ollama pull llama3.1
ollama serve
```

The model set in `OLLAMA_MODEL` must match the pulled one.

## Authentication

All `/api/` endpoints require authentication. Two methods are supported (see `DEFAULT_AUTHENTICATION_CLASSES`):

- **HTTP Basic** — `curl -u <username>:<password>`
- **Session** — log in at `http://localhost:8000/api-auth/login/` (used by Swagger UI)

JWT and token authentication are not implemented.

Quick check:

```bash
curl -u alice:pass1234 http://localhost:8000/api/collections/
```

All objects are owner-scoped: a user can see and modify only their own collections, documents, and logs.

## API request examples

> In PowerShell use `curl.exe` (the built-in `curl` alias is `Invoke-WebRequest`).

**Collections**

```bash
# List (paginated; default page size is 10)
curl -u alice:pass1234 http://localhost:8000/api/collections/

# Debug: show status code and headers
curl -i -u alice:pass1234 http://localhost:8000/api/collections/

# Search and ordering
curl -u alice:pass1234 "http://localhost:8000/api/collections/?search=work&ordering=name"

# Create
curl -u alice:pass1234 -X POST http://localhost:8000/api/collections/ \
  -H "Content-Type: application/json" \
  -d '{"name": "Work notes"}'

# Update / delete
curl -u alice:pass1234 -X PATCH http://localhost:8000/api/collections/1/ \
  -H "Content-Type: application/json" \
  -d '{"name": "Work notes 2026"}'
curl -u alice:pass1234 -X DELETE http://localhost:8000/api/collections/1/
```

**Documents**

```bash
# Create (collection is optional)
curl -u alice:pass1234 -X POST http://localhost:8000/api/documents/ \
  -H "Content-Type: application/json" \
  -d '{"title": "Vacation policy", "content": "28 days per year...", "collection": 1}'

# Filters: by collection, search in title/content, ordering
curl -u alice:pass1234 "http://localhost:8000/api/documents/?collection=1&search=policy&ordering=-created_at"

# Ask a question about a document (the main AI endpoint)
curl -u alice:pass1234 -X POST http://localhost:8000/api/documents/1/ask/ \
  -H "Content-Type: application/json" \
  -d '{"question": "How many vacation days do I get?"}'
```

`/ask/` response:

```json
{
  "answer": "28 days per year.",
  "log": {
    "id": 1,
    "document": 1,
    "question": "How many vacation days do I get?",
    "answer": "28 days per year.",
    "status": "ok",
    "error_message": "",
    "created_at": "2026-11-14T10:00:00Z",
    "tokens_used": 42,
    "latency_ms": 1234
  }
}
```

Ollama errors are mapped to HTTP statuses: `504` — timeout, `502` — unavailable/invalid response, `429` — rate limit.

**Question logs (read-only)**

```bash
curl -u alice:pass1234 "http://localhost:8000/api/questionlog/?status=ok&document=1"
curl -u alice:pass1234 "http://localhost:8000/api/questionlog/?search=policy&ordering=-created_at"
```

## Environment variables

| Variable | Default | Description |
|---|---|---|
| `SECRET_KEY` | dev placeholder | Django secret key |
| `DEBUG` | `False` | Debug mode |
| `ALLOWED_HOSTS` | `localhost,127.0.0.1` | Allowed hosts (comma-separated) |
| `DATABASE_URL` | — | PostgreSQL DSN, required |
| `POSTGRES_DB` / `POSTGRES_USER` / `POSTGRES_PASSWORD` | — | Parameters for the `db` container in `docker-compose.yml` |
| `OLLAMA_URL` | `http://localhost:11434/api/chat` | Ollama chat endpoint URL |
| `OLLAMA_MODEL` | `llama3.1` | Model used for requests |
| `OLLAMA_CONNECT_TIMEOUT` | `5` | Connection timeout, seconds |
| `OLLAMA_READ_TIMEOUT` | `120` | Read timeout, seconds |
| `AI_MAX_TOKENS` | `1000` | Maximum generated tokens (`num_predict`) |
| `AI_TEMPERATURE` | `0.3` | Generation temperature |
| `CONTEXT_CHAR_LIMIT` | `10000` | Maximum characters of a document passed in the prompt |

`PAGE_SIZE` is **not** configurable via environment: pagination is hardcoded in `settings.py` (`REST_FRAMEWORK["PAGE_SIZE"] = 10`).

## Tests

```bash
# locally (requires a reachable PostgreSQL from DATABASE_URL)
pytest
pytest --cov=apps

# in Docker
docker compose exec web pytest --cov=apps
```

`pytest-django` creates a separate test database (`test_<dbname>`). The Docker `POSTGRES_USER` (`kb_user`) is a superuser created by the official Postgres image, so it already has `CREATEDB`. For a non-superuser role, grant it manually:

```bash
docker compose exec db psql -U kb_user -d postgres -c "ALTER USER kb_user CREATEDB;"
```

Main tests: `apps/collections_app/test_collections.py` (CRUD, ownership, uniqueness, search/ordering), `apps/ai/tests.py` (Ollama client, error handling, prompts, logging).

## Architecture

```
apps/
├── collections_app/   # Collection: CRUD, owner-scoped, unique (owner, name)
├── documents_app/     # Document + QuestionLog: CRUD, filters/search, POST /{id}/ask/
└── ai/                # Ollama integration (no models/migrations)
    ├── client.py            # Ollama HTTP client, provider error mapping
    ├── prompts.py           # System prompt (answer-only-from-context) and template
    ├── services.py          # ask_document(): context building, truncation, logging
    ├── exceptions.py        # AIError hierarchy
    └── exceptions_handler.py # DRF exception handler (AIError → HTTP status)
```

- `Document` → `Collection` (`SET_NULL`), `QuestionLog` → `Document` (`CASCADE`).
- Access model: all querysets are filtered by `request.user`; a document's `collection` can only belong to the same user.
- `/ask/` is synchronous: takes the document `content` (up to `CONTEXT_CHAR_LIMIT`), injects it into the prompt, calls `OLLAMA_URL`, and writes a `QuestionLog` with status `ok`/`error`/`timeout`, tokens, and latency.

## Known limitations

- No JWT/token authentication — only Basic and Session.
- No RAG/vector search: the whole document goes into the prompt and is truncated to `CONTEXT_CHAR_LIMIT`; answers for large documents will be incomplete.
- No fallback model/provider: if Ollama is unavailable, the request fails with `502`/`504`.
- No queues/Celery: LLM requests are blocking and bounded by `OLLAMA_READ_TIMEOUT`.
- No file uploads (PDF/DOCX) — plain text in the `content` field only.
- No rate limiting or audit trail; question logs do not store the model or prompt.
- `runserver` inside the container (not production-ready), HTTPS/security headers not configured, default `SECRET_KEY` is a dev placeholder.
- Tests mostly cover collections and the AI layer; there are no tests for documents.

## Troubleshooting

**`database "knowledge_base" does not exist`** — the db name in `.env` (`POSTGRES_DB`) does not match `DATABASE_URL`. If you leave the Compose defaults, both resolve to `knowledge_base`; if you change one, change the other.

**`model 'llama3.1' not found`** — the model is not pulled. Run `docker compose exec ollama ollama pull llama3.1` (or `ollama pull llama3.1` for a local install).

**`Connection refused` on `localhost:11434`** — Ollama is not running. Check `docker compose ps`; the `ollama` service must be `Up` (it has a healthcheck).

**`Connection refused` on port 5432** — the `db` service is not ready yet. Wait for its healthcheck to pass (`docker compose ps` should show `healthy`).

**Swagger UI is empty** — open `http://localhost:8000/api-schema/` directly: it must return YAML generated without errors.
